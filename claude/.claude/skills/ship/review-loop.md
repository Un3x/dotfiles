# Review loop

Read at phase 5 (review) of `/ship`.

- Spawn a review subagent (fresh context, main model: review is judgment, `isolation: "worktree"` so its `gh pr checkout` never switches the branch under you) whose prompt is exactly:
  ```
  Run /review <pull_request_link>
  ```
  From round 2 it adds `Earlier rounds: <absolute paths of the review-round-*.md files in the main checkout's .notes/ (git worktree list)>`. Nothing else — the reviewer forms its own view from the PR and those rounds. `/review` carries the checklist, the four passes, the Codex second opinion and the layered-rails reviewer, so this phase adds nothing on top of it. Save the subagent's report **verbatim** to `.notes/<branch_name>/review-round-N.md` (the `review/output.md` shape, table and row order kept), then append `## Triage` with one line per row from 4 and per `rule` row, prefixed by its row number, score and type: `1. 8 bug fixed | rebutted: <why> | deferred: <where> | logged`. A paraphrased round file cannot be counted: a finding that recurs across rounds stops being measurable.
- Triage the report by score, highest first. An **open row** is a row from 4, not `pre-existing`, not yet fixed or rebutted: every open row is fixed. Rows under 4 stay as they are, with no triage line but for a `rule` row. `pre-existing` rows are triaged `deferred: <issue or note>`, never fixed in this PR. A `not run` line is noted in the session file `## Notes` and does not block the loop:
  - **No open row** → mark the session `shipped`, phase `done` (record the round count)
  - **Open rows** → fix on the same branch:
    1. **Challenge each row first.** A row is a claim: its constat, and its § Details line, no fix (`review/output.md`). Start from what that line carries. A `bug` or `test` row: its `Where:`, then its steps turned into a failing test. It fails → the row stands and that test is the red step. It passes, or the steps cannot be built → rebutted in review-round-N.md with what was tried. An `ask` row: its ask line checked against the issue, not rebutted by a test. A `rule` row: the quoted rule checked against its file and the diff. A `design`, `simplicity` or `readability` row: its holder or its cost checked by reading the code, then fixed without a red step, as a behaviour-preserving change; tests stay green. A `design` fix that reshapes more than the PR (a refactor of the system it fills) is a flag for the user, not a re-plan step. A `design` row that goes against a choice the plan states is a contradiction (global `CLAUDE.md`): neither fixed nor rebutted, it is reported to the user with the plan line quoted.
    2. **Re-plan**: append a `## Review round N` section to `.notes/<branch_name>/plan.md` — same format and same one rule as /plan ([`../one-rule.md`](../one-rule.md); one step per standing row: its failing test → fix, `remove <what>` alone for a removal, or `refactor <what>` for a behaviour-preserving fix; simplest fix only, flag rather than escalate). An **extra** the user wants kept is a scope change: ask, do not decide; a **missing** line is never rebutted, it is built or the issue is re-scoped by the user.
    3. **Re-ship**: implement the new steps with the [red-green-commit](../red-green-commit.md) cycle, push to the same branch (the PR updates). A fix goes into the commit whose story it tells (`commit` skill step 3: `--fixup`, autosquash, `--force-with-lease`) and into the file whose behaviour it covers, never into a file because its setup happens to make the test pass
    4. Spawn a **fresh** review subagent on the updated PR with the round-2 prompt, repeat
- **A `rule` row**, whatever its score, is logged as a repeat in the lessons ledger (triage `logged` under 4); from 4 it is also fixed like any other ([`../learn/SKILL.md`](../learn/SKILL.md) § Ledger row).
- **Round cap: 3.** If open rows remain after round 3, stop looping: note the open rows in the session file `## Notes` and surface them to the user. Past three rounds the problem is likely the design or the scope, not the fixes: say which you suspect.
- Update the session's Review round after each pass so resumption re-enters the loop correctly
